# Сетевой протокол ThirdWorld

Транспорт — **простой TCP-сокет** (`socket://mmog1.com:2500`), без TLS
(клиент умеет и `ssocket://`, но по умолчанию флаг `ssl=false`).

Протокол — **FLAP-подобный** (это фреймовый протокол из семейства OSCAR/ICQ;
в клиенте прямо есть строка `"Error in FLAP header"`). Все числа — **big-endian**
(сетевой порядок байт). Текст — **Windows-1251 (CP1251)**.

---

## 1. Кадр FLAP (общая обёртка) — класс `ae`

Любой пакет в обе стороны начинается с 6-байтового заголовка:

```
смещение  размер  поле         значение
   0        1     marker       0x2A  ('*')  — начало кадра
   1        1     channel      номер канала (1..5)
   2..3     2     sequence     порядковый номер (big-endian)
   4..5     2     length       длина payload в байтах (big-endian)
   6..      N     payload      тело пакета (length байт)
```

Проверки при разборе (`ae.a(byte[],off,len)`):
- байт `[0]` обязан быть `0x2A`, иначе ошибка `ak(130,2)`;
- `channel` обязан быть в диапазоне `1..5`, иначе `ak(130,3)`;
- `length` (`[4..5]`) обязан равняться `len-6`, иначе «Error in FLAP header».

### Каналы (channel)

| Канал | Назначение | Разбирается классом |
|------:|------------|---------------------|
| 1 | Коннект / логин | `l` |
| 2 | Игровые данные (группа+подтип) | `f` |
| 3 | Ошибка уровня FLAP | — (игнор) |
| 4 | Дисконнект | — |
| 5 | Keep-alive (пинг) | `ae` без тела |

> Примечание: `sequence` в наблюдаемых пакетах не критичен для логики
> (клиент шлёт логин с `seq=50`, данные с `seq=1`). Сервер может просто
> инкрементировать свой счётчик или зеркалить.

---

## 2. Пакет канала 1 — логин/коннект (`l`)

Payload — набор **TLV** (см. §4). Формируется в `l.b()`:

| TLV тип | Поле | Что |
|--------:|------|-----|
| 1 | login | имя пользователя (байты строки) |
| 2 | password | пароль |
| 4 | string | доп. строка (клиентский идентификатор) |
| 8 | version | 2-байтовое число `d` — версия/билд |

Собранный payload оборачивается в кадр FLAP: `marker=0x2A, channel=1, seq=50, length, …`.

---

## 3. Пакет канала 2 — данные (`f`)

Это рабочая лошадка: команды сервер↔клиент. Payload (`f.b()`):

```
смещение  размер  поле       что
   0        2     group      группа/семейство команды (big-endian)
   2        2     subtype    подтип/команда (big-endian)
   4..      N     data       данные команды
```

Полный пакет = FLAP-заголовок (`channel=1 или 2`) + этот payload.

Конструктор в клиенте: `f(int channel, int group, int subtype, byte[] data)`.
- `f.f()` → `group`
- `f.a()` → `subtype`
- `f.c()` → `data`

### Наблюдаемые group/subtype

**Клиент → сервер** (из `k`):

| group | subtype | Смысл |
|------:|--------:|-------|
| 1 | 0 | версия клиента (строка `"14022009"`) + размер экрана (2×short) |
| 4 | 12 | уникальный ID устройства (`z.getUnicalID`), 4 байта |
| 4 | 5 | логин + пароль (TLV 1=login, 2=password), CP1251 |

**Сервер → клиент** (разбор в `k.b`/`k.a`):

| group | subtype | Смысл (реакция клиента) |
|------:|--------:|--------------------------|
| 1 | 0 | приглашение к handshake → клиент шлёт версию/ID/логин |
| 4 | 0 | логин успешен → переход на игровой экран |
| 4 | 5 | сервер прислал уникальный ID (4 байта) → клиент сохраняет в RMS |
| 4 | 6 | некое событие (обновление состояния) |

> Точные номера остальных команд (строительство, юниты, карта, чат) кодируются
> теми же `group/subtype` — их можно доснять, гоняя клиент против мок-сервера
> из `server/` и логируя входящие `f`-пакеты.

## 4. TLV (тип-длина-значение) — класс `aj`

```
смещение  размер  поле
   0        2     type    (big-endian)
   2        2     length  (big-endian)
   4..      N     value   (length байт)
```

Запись: `aj.a(type, out, valueBytes)`. Чтение: `aj.a(bytes, off)` → value.

---

## 5. Кодировка чисел и текста — класс `t`

- `t.c(buf,off,v)` — записать 1 байт (`v & 0xFF`).
- `t.a(buf,off,v)` — записать 2 байта **big-endian**.
- `t.a(buf,off,long)` — записать 4 байта big-endian.
- `t.b(buf,off)` — прочитать 1 байт (unsigned).
- `t.c(buf,off)` — прочитать 2 байта big-endian (unsigned short).
- `t.a(buf,off)` — прочитать 4 байта big-endian (в long).
- `t.a(String)` — строка Unicode → байты **CP1251** (кириллица `А..я` → `0xC0..0xFF`,
  плюс отдельные Ё/ё и т.п.).
- `t.b(buf,off,len)` — байты CP1251 → строка Unicode.

Именно поэтому логин/пароль/чат нужно читать и писать **в CP1251**, а не UTF-8.

---

## 6. Как клиент читает поток — класс `g`

- `g.a(host,port,ssl)` — открывает `socket://host:port`, поднимает потоки in/out,
  запускает поток-читатель `run()`.
- `run()` — в цикле читает `available()` байт в кольцевой буфер `f[256]`,
  спит 20 мс; при `timed out`/ошибке помечает соединение закрытым.
- `a(ae pkt)` — сериализует пакет (`pkt.b()`) и пишет в сокет (синхронизированно).
- `d = {13,10}` — константа CRLF (маркер конца строки в текстовых ответах).

`ar` поверх `g` держит очередь и поток-приёмник: читает целые кадры FLAP
(`ar.h()` → `ae.a(bytes)`) и раздаёт `f`-пакеты в `k.b(f)`.
