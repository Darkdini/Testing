# Сценарий: подключение → handshake → логин → игра

Пошагово, как клиент общается с сервером (по коду `ar`, `k`, `l`, `z`).

```
Клиент                                              Сервер (mmog1.com:2500)
  │                                                        │
  │  1. TCP connect  socket://mmog1.com:2500               │
  │───────────────────────────────────────────────────────▶
  │                                                        │
  │                 2. FLAP ch2  group=1 subtype=0         │
  │◀───────────────────────────────────────────────────────  «представься»
  │                                                        │
  │  3. FLAP ch1(g1/s0): версия "14022009" + экран (WxH)   │
  │───────────────────────────────────────────────────────▶
  │                                                        │
  │  4. FLAP g4/s12: уникальный ID устройства (z.getUnicalID)
  │      (если ID уже есть в RMS; иначе шаг пропускается)   │
  │───────────────────────────────────────────────────────▶
  │                                                        │
  │  5. FLAP g4/s5: логин+пароль (TLV 1,2), CP1251, lower  │
  │───────────────────────────────────────────────────────▶
  │                                                        │
  │                 6a. FLAP g4/s5: выданный уникальный ID  │
  │◀───────────────────────────────────────────────────────  (клиент сохраняет в RMS)
  │                 6b. FLAP g4/s0: «логин ОК»              │
  │◀───────────────────────────────────────────────────────  → переход на игровой экран
  │                                                        │
  │           7. далее — игровые команды (g/s), чат,        │
  │              периодический keep-alive (channel 5)      │
  │◀──────────────────────────────────────────────────────▶
```

## Где это в коде

- **Шаг 1** — `ar.c()`: `g.a(al.q /*mmog1.com*/, al.g /*2500*/, false)`.
- **Шаги 2–6** — менеджер `k`:
  - `k.c(f)` (внутренний, group=1): на subtype 0 шлёт версию `"14022009"`,
    размер экрана (`ap.o × ap.p`), и, если есть, уникальный ID (`z.b()`).
  - `k.c()` (публичный): формирует и шлёт логин — берёт `ag.a` (login) и `ag.e`
    (password), приводит к нижнему регистру, кодирует в CP1251 (`t.a`),
    упаковывает в TLV (1=login, 2=password) и отправляет как `f(1,4,5,data)`.
  - `k.a(f)` (group=4): на subtype 0 — успех логина (открывает экран игры);
    на subtype 5 — читает выданный ID и сохраняет (`z.a(id)`).
- **ID устройства** — `z.b()`/`z.a()`: чтение/запись 4-байтового int в
  RMS RecordStore (это «привязка к устройству», аналог device-id).

## Что нужно серверу как минимум (MVP)

Чтобы клиент прошёл до игрового экрана, сервер должен:

1. Принять TCP-соединение.
2. Прислать `FLAP channel=2, group=1, subtype=0` (приглашение к handshake).
3. Принять от клиента версию/ID/логин, **не падать** на разборе.
4. Ответить `FLAP group=4, subtype=0` — «логин ОК».
   (Опционально сначала `group=4, subtype=5` с выданным ID.)
5. Держать соединение и отвечать на keep-alive (channel 5) тем же.

Дальше — реализовывать игровые команды по мере снятия их номеров
(логировать входящие `f`-пакеты мок-сервером и смотреть group/subtype).

Готовый учебный скелет такого сервера — в `server/mock_server.py`.
