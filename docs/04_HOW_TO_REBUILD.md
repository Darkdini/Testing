# Как воссоздать сервер («собрать что-то подобное»)

Главная правда: **игровые правила не лежат в клиенте.** Клиент — тонкий терминал
(см. `docs/... CLIENT_VS_SERVER`): он шлёт команды и рисует серверную разметку.
Значит «найти логику» = **воссоздать её**, а не извлечь. Это классический
private-server / server-emulation проект.

Есть две принципиально разные цели — выбери свою, от неё зависит всё:

| Цель | Что делаешь | Сложность |
|------|-------------|-----------|
| **A. Точная копия** оригинала | восстанавливаешь ИМЕННО те правила (стоимости, тех-дерево, бой) | высокая: правил в клиенте нет, нужны дампы трафика/вики/память игроков |
| **B. Свой сервер** на этом клиенте | берёшь клиент как «движок отрисовки» и пишешь СВОИ правила | средняя: ты сам решаешь балансы, главное — говорить на его протоколе |

Для обучения проще и честнее **B**: клиент — готовый фронтенд, а сервер — твой.
Позже часть правил можно подогнать под оригинал.

## Петля восстановления (главный метод)

```
1. Поднять сервер-разведчик (server/mock_server.py) — он логирует КАЖДЫЙ
   входящий пакет: канал, group, subtype, hex, попытку декода.
2. Запустить НАСТОЯЩИЙ клиент в J2ME-эмуляторе, направив его на localhost:2500.
3. Нажать в игре действие (открыть замок, построить дом...).
4. Увидеть в логе, какой пакет (g/s + данные) улетел на сервер.
5. Придумать/подсмотреть ответ, зарегистрировать handler на этот (g,s).
6. Смотреть, как клиент отрисовал ответ. Не так → правишь. Так → идёшь дальше.
7. Повторять: логин → главный экран → ресурсы → 1 здание → карта → чат → бой.
```

Каждый разгаданный `(group, subtype)` записывай в `docs/02_PROTOCOL.md` (таблицу команд).

## Как запустить настоящий клиент против своего сервера

Нужен **эмулятор J2ME** (телефона в железе у тебя нет). Варианты:

| Эмулятор | Плюсы | Как направить на свой сервер |
|----------|-------|------------------------------|
| **Microemulator** (Java, кроссплатформ) | простой, open-source | клиент коннектится к `mmog1.com:2500` — перенаправь хост |
| **FreeJ2ME** | активный, есть сеть | то же |
| **KEmulator** (Windows) | популярный у RE-сообщества | то же |

Клиент жёстко коннектится на `mmog1.com:2500` (поле `al.q`). Три способа увести
его на свой сервер:

1. **hosts / DNS**: прописать `mmog1.com → 127.0.0.1` (если эмулятор уважает hosts).
2. **Пропатчить JAR**: заменить строку `mmog1.com` на свой хост прямо в `al.class`
   (одинаковая длина — `localhost` короче, лучше `127.0.0.1` = 9 символов vs 9,
   ровно, либо свой домен той же длины), пересобрать zip. Это самый надёжный путь.
3. **Перенаправление на уровне сети** (iptables/redsocks) — если эмулятор в Linux.

> Патч строки — обычно самый простой: JAR это ZIP, `al.class` содержит literal
> `mmog1.com` (9 байт). Замена на `127.0.0.1` (тоже 9 байт) не ломает длину
> constant pool. Затем переупаковать и подписать не нужно (для эмулятора).

## План по этапам

**Этап 0 — окружение.** Поставить эмулятор, убедиться, что JAR запускается,
показывает логотип/меню логина.

**Этап 1 — логин (готово в скелете).** Handshake + принять логин + ответить OK.
Цель: клиент уходит с экрана логина на главный.

**Этап 2 — главный экран замка.** Клиент запросит ресурсы/состояние. Ответить
снапшотом (ресурсы, скорости, ёмкость склада — клиент сам докрутит числа).
Разгадать формат пакета `get resources`.

**Этап 3 — окна через разметку.** Научиться отдавать серверную разметку окна
(`{i..}` картинки, `{u11|..}` виджеты: TextBox, ComboBox, CollectButton). Это
твой «HTML» — им ты рисуешь любые экраны. Разобрать грамматику на живых примерах.

**Этап 4 — одно здание.** Постройка/апгрейд: принять команду, ответить временем
(`Get Build Rest Time`) и новым состоянием.

**Этап 5+** — карта соседей (`getNeighbourhoodMap`), сообщения
(`getOneFullMessage`), альянсы, бой. Каждый — тот же цикл «наблюдай → отвечай».

## Что уже можно достать из клиента (помогает, но это не «логика»)

- `texts/strings.txt` — названия и описания зданий/юнитов (локализация).
- Картинки зданий/юнитов/ландшафта (`build/`, `units/**`, `ground/**`) — с их
  именами уже понятно, какие сущности есть в игре.
- Грамматика разметки окон (`{i<n>}`, `{u11|...}`, элементы ComboBox/TextBox/
  CollectButton/ImageElement/Label) — «язык», которым сервер рисует UI.
- Формулы отрисовки/интерполяции ресурсов (`p.a()`): ресурс растёт
  `rate * seconds / 3600`, ограничен ёмкостью склада — значит серверу достаточно
  прислать текущее значение, скорость и ёмкость, остальное клиент дорисует.

---

## Юридически/этично

Делать приватный сервер для игры, к которой у тебя есть клиент, для обучения и
совместимости — нормальная практика RE. Не трогай чужие живые серверы, не
распространяй чужие ассеты как свои. Свой сервер + свои правила = твой проект.
